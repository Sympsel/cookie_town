# 曲奇小镇 · 打包上线全流程（第一版）

目标：把应用部署到**阿里云 Linux 服务器**，全新 MySQL，经 **Caddy 反向代理 + Let's Encrypt 证书**对外提供 `https://cookie-town.cn`。
静态资源采用**外置 wwwroot 目录**（jar 与 wwwroot/、config/、uploads/ 并列，从部署目录启动，零代码改动）。

> 命令以 **Ubuntu 22.04/24.04（apt）** 为主；RHEL 系 / Alibaba Cloud Linux（dnf）差异处已标注。
> 全程用 root 或 sudo 执行。`<服务器IP>`、`<...>` 为占位符，请替换。

---

## 0. 架构与部署目录布局

```
公网用户 ──HTTPS(443)──> Caddy(自动证书) ──HTTP──> 127.0.0.1:8080  java -jar cookie-town.jar
                                                          │
                                                          ├─ ./config/config.json   (数据库/JWT/名单，外置)
                                                          ├─ ./wwwroot/             (前端 html/css/js，外置)
                                                          └─ ./uploads/             (用户上传，外置、可写)
                                                          └─ MySQL 127.0.0.1:3306   (库 cookie_town)
```

服务器部署目录固定为 `/opt/cookie-town`：

```
/opt/cookie-town/
├── cookie-town.jar          # 后端可执行 jar（打包产物）
├── config/
│   └── config.json          # 生产配置（含真实密码/密钥，不入库）
├── wwwroot/                 # 前端静态资源
├── uploads/                 # 运行时上传目录（服务账号可写）
└── deploy/                  # 本目录的部署文件（systemd/Caddy/nginx/指南）
```

**关键点**：`WorkingDirectory=/opt/cookie-town` 决定了 `file:wwwroot/`、`file:uploads/`、`./config` 的解析位置，所以必须从该目录启动。

## 1. 本机打包（Windows 开发机）

在 PowerShell 里运行打包脚本，产出可直接上传的 `dist/` 与 `cookie-town-dist.zip`：

```powershell
cd D:\shared\Code\javaCode\cookie_town
powershell -ExecutionPolicy Bypass -File deploy\package.ps1
```

脚本做了三件事：`mvn clean package -DskipTests`（JDK 25）→ 组装 `dist/`（jar + wwwroot + config 模板 + deploy）→ 压缩成 `cookie-town-dist.zip`。

产物 `target/cookie-town.jar` 即后端可执行 jar（`pom.xml` 已设 `finalName=cookie-town`）。

## 2. 服务器准备（阿里云 ECS）

### 2.1 安全组 / 防火墙

在阿里云控制台 **安全组**放行入方向：

| 端口 | 用途 | 来源 |
|---|---|---|
| 22 | SSH | 你的 IP（建议限白名单） |
| 80 | HTTP（证书签发挑战 + 跳转 HTTPS） | 0.0.0.0/0 |
| 443 | HTTPS | 0.0.0.0/0 |

> **不要**放行 8080（后端）与 3306（MySQL）到公网——它们只在本机被 Caddy / 应用访问。
> `.cn` 域名解析到内地 ECS 的 80/443 需已 ICP 备案（本项目域名已备案）。

若系统内还启用了 ufw/firewalld，同样放行 80/443：
```bash
ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 22/tcp && ufw enable   # Ubuntu
```

### 2.2 安装 JDK 25（Temurin 二进制，跨发行版通用）

```bash
cd /opt
curl -L -o jdk25.tar.gz "https://api.adoptium.net/v3/binary/latest/25/ga/linux/x64/jdk/hotspot/normal/eclipse"
tar -xzf jdk25.tar.gz
JDK_DIR=$(ls -d /opt/jdk-25* | head -n1)
ln -sfn "$JDK_DIR" /opt/jdk-25
/opt/jdk-25/bin/java -version    # 应显示 openjdk version "25..."
```
> systemd 单元里 `ExecStart` 用的就是 `/opt/jdk-25/bin/java`，与上面软链一致。

### 2.3 安装并初始化 MySQL 8

```bash
apt update && apt install -y mysql-server          # Ubuntu
# RHEL/Alibaba Cloud Linux： dnf install -y mysql-server   （服务名为 mysqld；若无包先加 MySQL 官方 yum 源）
systemctl enable --now mysql                       # RHEL 系： systemctl enable --now mysqld
mysql_secure_installation                          # 交互：设 root 密码、移除匿名用户、禁止 root 远程等
```

创建**库**与**专用账号**（不要用 root 跑应用）：
```bash
mysql -u root -p
```
```sql
CREATE DATABASE cookie_town CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'cookie'@'localhost' IDENTIFIED BY '<数据库专用强密码>';
GRANT ALL PRIVILEGES ON cookie_town.* TO 'cookie'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```
> 应用只建表不建库，所以 `cookie_town` 库必须**先手动创建**，否则启动失败。
> `utf8mb4` 保证中文与 emoji 正常存储。

### 2.4 安装 Caddy（推荐，自动 HTTPS）

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
systemctl status caddy --no-pager      # 装完会自带默认站点，稍后被我们的 Caddyfile 覆盖
```
> 想用 Nginx 见第 6.3 节。

```powershell
cd D:\shared\Code\javaCode\cookie_town
```

```bash

ls -R /opt/cookie-town                                # 确认 jar / wwwroot / config / deploy 就位
mkdir -p /opt/cookie-town/uploads                     # 运行时上传目录
```

### 3.3 创建低权限服务账号并授权

```bash
useradd --system --home /opt/cookie-town --shell /usr/sbin/nologin cookietown
chown -R cookietown:cookietown /opt/cookie-town
# 上传目录必须可写
chmod -R u+rwX /opt/cookie-town/uploads
```

## 4. 生产配置 config.json

编辑 `/opt/cookie-town/config/config.json`，把所有占位符替换为真实值：

```bash
nano /opt/cookie-town/config/config.json
```

必须修改的项：
- `mysql.user` / `mysql.password`：填第 2.3 步创建的 `cookie` 账号与密码。
- `jwt-secret`：**至少 32 字节**强随机串。生成：
  ```bash
  openssl rand -base64 48
  ```
- `first-admin`：`[用户名, 密码]`，首个管理员账号（不存在则用此密码创建为 Admin）。
- `developers`：开发者用户名名单（启动自动打「开发者」标签）。
- `main-town`：主镇名称/简介/镇长用户名。
- `develop-mode`：**必须 `false`**（生产）。
- `clean-and-launch`：**必须 `false`**（`true` 会清库重建，仅在确认要清档时临时用一次）。

```bash
chown cookietown:cookietown /opt/cookie-town/config/config.json
chmod 600 /opt/cookie-town/config/config.json         # 含密钥，收紧权限
```

## 6. 域名 + HTTPS 反代

### 6.1 DNS 解析（阿里云 DNS 控制台）

添加两条 A 记录，均指向 `<服务器IP>`：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `@` | A | `<服务器IP>` |
| `www` | A | `<服务器IP>` |

等待生效：`ping cookie-town.cn` 或 `dig +short cookie-town.cn` 应返回服务器 IP。

### 6.2 Caddy（推荐路径）

```bash
cp /opt/cookie-town/deploy/Caddyfile /etc/caddy/Caddyfile
caddy validate --config /etc/caddy/Caddyfile         # 语法自检
systemctl restart caddy
journalctl -u caddy -f                               # 观察证书申请日志
```
Caddy 会自动为 `cookie-town.cn` 与 `www.cookie-town.cn` 申请并**自动续期** Let's Encrypt 证书。
验证：
```bash
curl -I https://cookie-town.cn
curl -I https://www.cookie-town.cn
```
应返回 `HTTP/2 200`（或 80 自动 301→443）。浏览器打开 `https://cookie-town.cn` 应看到曲奇小镇首页且证书有效。

### 6.3 Nginx 备选路径（若不用 Caddy）

```bash
apt install -y nginx certbot python3-certbot-nginx
cp /opt/cookie-town/deploy/nginx-cookie-town.conf /etc/nginx/conf.d/cookie-town.conf
nginx -t && systemctl reload nginx
certbot --nginx -d cookie-town.cn -d www.cookie-town.cn    # 自动改配置 + 签发证书
```

## 8. 日常运维

### 8.1 重新部署（更新版本）

本机重打包后，**只覆盖 jar（前端有改动再同步 wwwroot）**，切勿动 `config/config.json` 与 `uploads/`：
```powershell
# 本机
cd D:\shared\Code\javaCode\cookie_town
powershell -ExecutionPolicy Bypass -File deploy\package.ps1
scp target\cookie-town.jar root@<服务器IP>:/opt/cookie-town/cookie-town.jar
# 如前端有改动：
scp -r wwwroot\* root@<服务器IP>:/opt/cookie-town/wwwroot/
```
```bash
# 服务器
chown cookietown:cookietown /opt/cookie-town/cookie-town.jar
systemctl restart cookie-town
journalctl -u cookie-town -f
```

### 8.2 备份（数据库 + 上传文件）

```bash
mkdir -p /opt/backup
mysqldump -u cookie -p cookie_town > /opt/backup/cookie_town_$(date +%F).sql
tar -czf /opt/backup/uploads_$(date +%F).tgz -C /opt/cookie-town uploads
cp /opt/cookie-town/config/config.json /opt/backup/config_$(date +%F).json
```
建议加 crontab 每日自动备份并异地保存。

### 8.3 常用命令

```bash
systemctl restart cookie-town          # 重启后端
journalctl -u cookie-town -n 200       # 最近 200 行日志
journalctl -u caddy -f                 # 反代/证书日志
```

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 后端起不来，日志 `Access denied for user 'cookie'@'localhost'` | config.json 的 mysql 账号/密码与第 2.3 步创建的不一致 |
| `Unknown database 'cookie_town'` / 建表失败 | 库没先建；应用只建表不建库，执行第 2.3 步的 CREATE DATABASE |
| `Port 8080 was already in use` | 有旧实例：`ss -ltnp \| grep 8080` 找到 PID 后停掉，或 `systemctl restart cookie-town` |
| Caddy 证书签发失败 | ①DNS 未指向本机 ②安全组没放行 80 ③域名备案异常；看 `journalctl -u caddy` |
| 访问 `/uploads/...` 404 | uploads 目录不存在或不可写；确认第 3.2/3.3 步已建目录并 chown 给 cookietown |
| 上传大图 413 | Nginx 需 `client_max_body_size`≥20m（备选 conf 已含）；Caddy 默认不限制 |
| 中文乱码 | 库/表须 utf8mb4；systemd 已设 `-Dfile.encoding=UTF-8` |
| 想清档重建 | 临时把 config.json 的 `clean-and-launch` 改 `true` 重启一次，成功后**务必改回 `false`** |

## 10. 生产加固建议（后续迭代）

- **Schema 迁移**：当前 `ddl-auto=update` 适合起步，但不会删列、且可能改动列类型。生产建议后续引入 **Flyway/Liquibase** 管理版本化迁移，并把 `ddl-auto` 改为 `validate`。
- **数据库账号**：已用专用账号 `cookie`（非 root），最小权限仅 `cookie_town` 库。
- **密钥管理**：`jwt-secret`、DB 密码只在服务器 config.json（权限 600），不入库、不进日志；`jwt-secret` 上线后勿随意更换（会使已发 token 失效）。
- **端口最小暴露**：公网只开 22/80/443；8080、3306 仅本机。可进一步把后端绑定到 `127.0.0.1`（application.yml 设 `server.address=127.0.0.1`）。
- **HTTPS 强制**：Caddy 默认已 80→443 跳转；Nginx 用 certbot 后同样自动跳转。
- **日志轮转**：为 `/var/log/caddy/` 与应用日志配置 logrotate，避免占满磁盘。
